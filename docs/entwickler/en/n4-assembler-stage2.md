# Stage N4: Assembler level 2 (status and structure)

German version: [../de/n4-assembler-stufe2.md](../de/n4-assembler-stufe2.md). Builds on [n2-assembler.md](n2-assembler.md): variables, repetition, macros, scopes, structures and more directives, producing the same results as `vcc`. Everything runs in Xemu (Mac) and passes the differential tests; not checked on a real MEGA65.

## What level 2 does

| Area | Scope | File |
|---|---|---|
| Variables | `.var`, `.set`, `name = …`, `name op= …` (`+ - * / % & \| ^ << >>`); a value counts from the line in which it is set | `stage2.asm` |
| Repetition | `.repeat n [, var]`, `.for i = a, condition, step`, `.for i in range(…)`, `.for c in [list]`, `.next`, `.break`, `.continue`; the loop variable only exists in the block and hides one of the same name | `stage2.asm` |
| Macros | `.macro`/`.endmacro`, parameters by text substitution (parentheses and defaults `p=value`), calls with or without parentheses, call before definition, `@label` unique per call, `.exitmacro`, nesting up to 64 frames | `stage2.asm` |
| Scopes | `{ }` (named by the label on the line, otherwise anonymous), `.namespace name {`; innermost scope wins, `scope.name` from outside, local labels per scope, variables hide outer ones | `stage2.asm` |
| More directives | `.page [n]`, `.pseudopc`/`.endpseudopc`/`.realpc`, `.fill` and `.lohifill` with expression and loop variable, `.struct`, `.enum`, `.rta` with list, `.basicstub target, line, "text"`, `.assert`, `.error`, `.warning`, aliases `.db .dw .dbyt .long`, `//` comments | `dir2.asm`, `asm.asm` |
| Functions | built in: `abs sign min max int floor ceil round next align pow sqrt sin cos tan asin acos atan atan2 exp log log2 log10 len range`; user defined: `.function name(a, b) = expression` (one expression, up to 16 levels deep, no recursion), a call needs the bracket directly after the name | `func.asm`, `math.asm`, `list.asm` |
| Floating-point numbers | literals `2.5`, `1e3`, `1.5e-2`, `pi`; arithmetic `+ - * /`, comparisons, `&& \|\| !`; `int`/`floor`/`ceil`/`round`; storable in `.var`; where an integer is needed the value is truncated towards zero (vcc warns W202 there) | `numx.asm`, `math.asm` |
| Lists | `[a, b, c]`, `t[i]`, `t[-1]`, `t[a:b]`, `t[:n]`, `t[n:]`, `list + list`, `list * n`, `len`, `range`, lists in lists; `.byte`/`.word`/`.dword` output lists flat; `.for x in list`; `.var t = []` with `t += [..]` | `list.asm` |
| Text | `{name}`, `{$hh}`, `{nnn}`, `{name*n}`, `{{` in strings; `.encoding "name" { … }` | `text2.asm`, `charnames.asm` |

`charnames.asm` is generated by `tools/gen_charnames.py` from `vendor/vintagecoder/data/chars/petscii.json` (49 names including BASIC names and aliases).

- **`.target` is optional**: VC65 only builds for the MEGA65. Without `.target` the target is `mega65`; `.target mega65` is accepted, any other target reports an error (E207). VintageCoder sources with `.target mega65` build unchanged (tests `t00_*` without, `t17_var` with the line).

## How it works

**Source stack.** The assembler keeps reading through the 32-bit pointer `SRC`. At the end of a block a loop resets `SRC` to the start of its body; a macro call writes the body, with parameters substituted, into a text buffer and continues reading from there. The end of the buffer (character 0) leads back to the calling line. Every running loop and every macro call is a **frame** (32 bytes) on a stack; `.break`, `.continue` and `.exitmacro` unwind frames and restore the `.if` depth.

**Macros.** Before the first pass `mac_scan` finds all `.macro` lines (a macro may be called before its definition); the table remembers the name (lower case) and the text pointer behind the name. On a call the arguments are split as `vcc` does (a leading `(` and a trailing `)` of the argument text are dropped, commas at bracket depth 0 separate), paired with the macro header (defaults fill missing arguments, otherwise **E209**) and the body is copied character by character: a name that exactly equals a parameter is replaced by the argument (not inside strings and comments); `@name` becomes `.zqNNNNname` with a number new for each call (a local label, hence unique per call). The call number restarts in every pass so all passes produce the same names.

**Variables** live in their own table (always the current value, no "old/new" as for labels) and are cleared at the start of each pass; when looked up they take precedence over labels of the same name in the same scope.

**Scopes.** The path of the open scopes is kept as text (`a.b.`); names are given the path when created and tried from the innermost scope outwards when looked up. Anonymous scopes are called `#hhhh` (counter per pass). `{`/`}` after `.encoding` form an encoding block on the same stack (restores the encoding, labels stay visible).

**Soft errors.** `.assert` and `.error` count like value errors only in the last, stable pass (`E207`).

## Memory (level 2)

Bank 4 (`$0004_0000`): variables `$0000–$1FFF`, list memory `$2000–$3FFF`, frames `$4000–$47FF`, function table `$4800–$4BFF`, argument stack `$4C00–$5FFF` (9 bytes per value), macro table `$6000–$6FFF`, expansion buffer `$7000–$BFFF`, symbol hash table `$C000–$FFFF` (8192 slots of 2 bytes, linear probing; hash = rotate left by 3 and add the character). **Bank 6 and above do not exist in chip RAM** (only banks 0, 1, 4, 5; banks 2 and 3 are the ROM area); a first draft using bank 6 failed for exactly that reason. In the concept's bank plan banks 4 and 5 are working and table banks; the level 2 data belongs to the role "assembler working data".

Zero page: `$00–$0d` (`P6`, `P7`, `FP`, `S2T`) and `$fc/$fd` (`MP`); the rest unchanged from `zp.asm`. The test programs now leave their results at `$C200`. The program has grown so large (up to about `$7E00`) that the tests' base page had to move from `$6F00` to `$9F00`; it must lie in RAM below `$A000` (BASIC ROM) and must not overlap the code. In the finished VC65 the code lives in bank 4, so this is no issue there.

## Limits (still open)

- **Non-ASCII characters (UTF-8, umlauts):** In comments and in strings for `.text`, `.petscii` and `.byte` VC65 assembles like `vcc` (byte-identical). **Differences from `vcc`:** labels, constants and character literals (`'ü'`) with non-ASCII characters are reported as errors by VC65 (E205 or E201), `vcc` accepts them; `.screencode` with non-ASCII characters gives a different code (for example `$C3` instead of `$43` for the first byte of ü). Recommendation: umlauts only in comments and in strings for `.text`, `.petscii` and `.byte`; identifiers and `.screencode` with ASCII only. The editor shows every byte above 127 as a dot (a ü as two dots); the bytes are saved unchanged.
- **Macro parameters:** at most 16 (`MAXPAR` in `stage2.asm`; table `ptbl` in the image, 32 bytes per parameter). `vcc` has no limit (E209 only checks the number of call arguments). More parameters in the macro declaration report E900 (`ERR_E900`, VC65 only), more arguments than parameters E209 as in `vcc`. Test: `tools/errtest.py` (`par16`, `par17`).
- **Floating-point numbers are fixed point 32.32**, not IEEE double as in `vcc`: resolution 2.3·10⁻¹⁰, 32-bit integer part. The trigonometric, logarithmic and root functions (CORDIC, Newton, series) agree up to rounding errors around 10⁻⁸; results within about 2⁻²² of an integer are set to that integer (`sin(pi/2)` = 1, `log10(1000)` = 3, as in `vcc`). Edge cases where an exact half value lies on one side or the other only in double precision may differ. Integers are 32 bit (vcc: 64 bit).
- A list of more than about 900 elements exhausts the list memory (8 KB, `E211`); `x += [..]` copies the list each time.
- `.for x in range(…)` runs without a list (even very long ranges), whereas `range(…)` in an expression creates the list.
- `.run` is read but without effect (`.cycles`: see n2-assembler.md). `.atascii` (Atari) is not planned.
- `.fill`/`.lohifill` evaluate the expression per element (simple, but slower for very large tables).
- Nesting depth: 64 frames, 7 scopes, names up to 31 characters including the scope path (otherwise `E211`).
- Struct fields whose type is a structure with count > 1 create the sub-fields only for the first element (as `vcc` does).

## Speed

Symbols are found through a hash table (before: linear, 37.5 s). Self-hosting (8477 lines, 4 passes) in Xemu at 40 MHz: **5.8 s**, i.e. about 0.7 s per 1000 lines over all passes; the concept's target (under 1 s for 1000 lines) is met. Measured with the CIA counters (`tools/selfhost.py`); Xemu has no wait states, not checked on a real MEGA65.

## Tests

`tests/asm/t17_var` … `t27_list` cover the level 2 features (differential test against `vcc`); the examples of the help run through `tools/conform.py` (**61 of 67 identical**, see n2-assembler.md). Self-hosting (`tools/selfhost.py`) still passes.

### MEGA65 example projects from VintageCoder

`tools/examples.py [name …]` copies an example project (read-only use) to `build/ex/<name>`, lets `vcc build` create the export files (`build/export/*.asm`) and then compares `vcc` and the native assembler in Xemu byte for byte. Status: **cputest, jumprun, music_demo, pal_demo and prallball (224 KB, 7531 lines) are identical**. Found and fixed on the way: macros in files pulled in with `#include` were missed by the pre-scan; `aslq q`/`lsrq q` (Q as operand); anonymous labels with several signs (`jmp ++`, `bne --`); more than 16 files in one project (from the 17th on they share the last name slot, only the mapping of errors to files suffers). Open: **`hello`** uses chip symbols (`vic2.border`, from `data/chips/*.chip.json`) that the native assembler does not know yet; `play_demo`, `standard_charsets` and `tiles_demo` have no source. Paths leaving the project root (`../../common/…`) are normalised to `common/…` by the native assembler; the test therefore stores those files under that name.

**E300 (code or label before the first `.org`):** Like `vcc`, the native assembler now reports E300 when a byte is emitted or a label is defined before the first `.org` (or `*=`); constants, macro definitions and an `.align` without effect stay allowed. Tested in `tools/idetest.py` (`e300_code`, `e300_marke`).
