# Debugger (N8, stages 1 and 2)

German version: [../de/n8-debugger.md](../de/n8-debugger.md). Sources: `src/debug/` (disassembler `dis.asm`, tables `dtab.asm`, core `dbg.asm`, UI `dbgui.asm`, session `dsess.asm`, overlay `overlay.asm`), bridge in `src/ide/boot.asm`.

## Use (keys provisional, unchecked on the device)
- **Ctrl+E** assemble, **Ctrl+G** toggle a breakpoint on the cursor line (address from the line table of the last assembly; if the text changed since, the IDE says "Erst uebersetzen"), **Ctrl+D** start the program in the debugger (stopped at the entry point).
- In the debugger: **F1 / s** single step, **F3 / n** step over (a `JSR` runs through), **F5 / c** continue to the next breakpoint, **V** program screen (until the next key), **F7 / q / STOP** end the session (program state is discarded), cursor down/up scroll memory by 32 bytes.
- Screen: row 0 title and stop address, 1 registers A X Y Z B SP PC, 2 Q (Z Y X A) and flags, 5–14 disassembly from PC, 16 source line (from the line table), 18 stack, 20–23 memory.

## Design
- **Stopping:** `BRK` (`$00`) is written at the location, the original byte kept. The KERNAL pushes B, Z, Y, X, A and jumps through the vector `$0316` to `ktrap` (bridge, bank 0, `$1380`). The frame from `SP+1` is B, Z, Y, X, A, P, PCL, PCH; PC − 2 is the stop address.
- **Saving:** `ktrap` switches to the IDE map and calls `dbg_trap` (overlay). It saves registers, zero page (`$1500`) and the test program's stack (`$1200`, at most 224 bytes), removes all inserted `BRK` and returns through the tail of `krun` (`kr_after`) to the **session loop**.
- **Resuming:** `dbg_resume` restores stack and zero page, inserts the breakpoints (except at PC) and jumps through `kgo` with `RTI` into the test program. The loop must call `krun` and `dbg_resume` at the **same stack depth** so the return address matches.
- **Stepping:** `dbg_next` decodes the instruction at PC (`dis_one`, tables from `45gs02.cpu.json`) and sets temporary breakpoints on every possible next instruction: fall-through, branch target (both for conditional, only the target for BRA/LBRA), `JMP` target, `JSR` target ("into"; if it is at `$C000` or above, i.e. ROM, the subroutine runs through) or fall-through ("over"), the return address from the saved stack (`RTS`, `RTN`, `RTI`; returning into the IDE frame means the program ends), indirect jumps after reading the pointer.
- **Continue** at a breakpoint: first a hidden step, then with all breakpoints. A genuine `BRK` of the program is skipped.
- **Disassembler:** text format as `vcc dis` (`lda ($20),y`, `bne $2016`, `bbr3 $12,$201c`, `lda [$20],z`, `ldq $30`, `asl a`, `lsrq q`). `tools/distest.py` compares it with `vcc dis` on random valid instruction sequences: 25 sequences of 60 instructions each identical.
- **Line table** (`asm.asm`, `ln_hook`): one entry per source line with output (position, address, length) in the Attic at `$0860_0000`, main file only; output of macros and includes goes to the calling line (vcc assigns macro bytes to the lines of the macro body: `tools/linetest.py` reports `t19_macro`, `t23_misc` as known deviations, all other examples are equal). Fill bytes of `.org` and `.page` do not count, those of `.align` do (as in vcc).

## Emergency key (NMI)
If a program is stuck in an endless loop, the **RESTORE key** (raises an NMI) brings the IDE back: `krun` and `dbg_resume` use `kvec_set` to set the NMI vector (`$0318`) to `knmi` next to the BRK vector (`$0316`) and restore both in `kr_after`. `knmi` acknowledges a CIA-2 NMI (`lda $dd0d`), records `kt_nmi = 1` and goes through `dbg_trap` like `ktrap`; the PC is then the interrupted location (for `BRK` PC − 2). The display says "unterbrochen (Notfalltaste) bei $xxxx", registers and stack are right (the KERNAL's NMI frame has the same form as the BRK frame: B, Z, Y, X, A, P, PCL, PCH). Continue, step and end work as after a breakpoint. If the overlay is not loaded yet (program started with Ctrl+R), `ktr_go` just aborts, `krun` returns with `kr_trap = 2` and the IDE reports "Programm unterbrochen (Notfalltaste)".
- **Test in Xemu:** a CIA-2 timer raises the NMI (`tools/dbgtest.py`: interruption, a step afterwards, interrupting again after continue, abort without the debugger). On resuming, `kgo` acknowledges accumulated CIA-2 NMIs, otherwise no new edge would come.
- **Unchecked:** the RESTORE key itself on a real MEGA65 (the KERNAL treats STOP + RESTORE as a warm start; whether the path through `$0318` works the same there belongs to the hand test). If the PC is in ROM (for example in `GETIN`), you can continue but not step (no breakpoints can be set in ROM).

## Debugger screen and program screen (`src/debug/dvid.asm`)
The debugger has its **own screen**: characters at `$0004_D200` (CPU address `$D200` in block 6, inside the editor screen area), colours at `$0FF8_1000` (`DV_COL`; until 2026-11-23 `$0FF8_0800`, which is inside the colour RAM of the 50-row editor). The VIC-IV is pointed at them with the pointer registers SCRNPTR (`$D060–$D063`) and COLPTR (`$D064/$D065`); screen, colour RAM and graphics memory of the test program stay untouched. For this the overlay keeps three snapshots of the VIC registers `$D000–$D07F`: `DV_I` (state of the IDE at session start), `DV_T` (state of the program when it stopped) and `DV_D` (`DV_I` with the pointers to the debugger screen). At the first stop `DV_T` is saved and `DV_D` loaded, before every resume `DV_T` is loaded again (`dsr`), at the end of the session `DV_I` (`dv_end`). **V** (or `$10`) shows the program screen until the next key.
- **Register access:** in the IDE map the I/O area is hidden. `dv_on` briefly switches to a map without block 6 (blocks 4, 5, 7 → bank 4, MAP Z=`$B4`) in which `$D000` is visible; the code therefore sits in the overlay in **block 7** (the overlay now lives at `$E000`, bank 4 `$4E000`, no longer at `$D000`), block 6 only holds main-program code that is not needed at that moment. Registers are written in ascending order (`$D011/$D016/$D018/$D031` reset the VIC-IV registers, these come afterwards); `$D02F` (unlock) and the acknowledge registers `$D019`, `$D01E`, `$D01F` are skipped.
- **Test:** `tools/dbgtest.py` checks with the screen text that Xemu saves on exit (`-dumpscreen`) that after the stop the debugger is shown and after V the program's text; a photo of the scene is in `docs/screenshots` (`tools/screens.py`). The other tests now read the debugger screen (`dscreen`).
- **50-row IDE:** the debugger screen has 25 rows. `dv_start` briefly clears V400, saves the registers computed by the hardware as the basis of `DV_D` and restores `DV_I` (50 rows); details and measurements in [n1-ide.md](n1-ide.md), section "50-row screen".
- **Limits:** if a program changes screen or colour RAM at places the debugger also uses (colour RAM from `$0FF8_1000`), you will not see that cleanly after stopping; programs with their own video mode (bitmap, sprites) are preserved through the register snapshots. Unchecked on a real MEGA65 (SCRNPTR/COLPTR and the unlock are checked in Xemu).

## Overlay VC65D
The main program (`VC65`, at most up to `$CFFF` because BASIC cannot load above that due to I/O) leaves no room for the debugger. The debugger therefore lives in the file `VC65D` (PRG with header `$E000`) and is copied by `ov_ensure` through the KERNAL file routines (drive 8) to bank 4 `$4E000` on the first Ctrl+D. For this the IDE map shows bank 4 at `$2000–$FFFF` (blocks 1–7); the vectors `$FFFA–$FFFF` point to an IDE `RTI`. The overlay entry at `$E000` is a jump table (`ide_debug`, `dbg_trap`). `tools/build_ide.py` builds `VC65`, derives `build/ovsyms.asm` (all names as constants) from its label file, builds `VC65D` from that and puts both on a D81.

## Test
- `tools/dbgtest.py`: assemble a program in the editor, start it in the debugger; stops after start, step, `JSR` into, over, return, continue to the end (memory mark `$C500`) and a breakpoint set on a line with Ctrl+G. Addresses from the `.vcdbg` of vcc. Status: all cases identical.
- `tools/distest.py`, `tools/linetest.py` see above.

## Limits and open points
- Watches and data breakpoints (stage 3), a breakpoint in the ROM area from `$C000`, a program that destroys the stack or zero page, and programs with their own IRQ/NMI operation are not covered; a program without `RTS` can be interrupted with the emergency key (RESTORE).
- Breakpoints in macro bodies and include files are not possible yet (line table for the main file only).
- Everything is checked in Xemu only; the BRK/KERNAL paths on a real MEGA65 belong to the hand test.
